# DayMate UX/UI 가이드

새 칸·화면을 만들거나 기존 화면을 올릴 때 먼저 읽는다. **이미 사용자가 확정한 것만** 적었고, 근거는 CLAUDE.md의 해당 장에 있다. 새로 확정되는 화면 원칙은 여기와 `src/styles.js`의 `UI`에 함께 반영한다(CLAUDE.md에는 한 줄 + 이 문서 링크).

값의 원본은 `src/styles.js`의 `UI`다. 숫자를 화면 파일에 직접 쓰지 말고 이 값을 쓴다.

---

## 0. 전제

- **큰 글씨가 기본이다.** `.dm-phone`에 CSS `zoom: 1.1`이 걸려 있어 아래 px는 화면에서 1.1배로 보인다. 글씨 크기를 `font-size`로 일괄 조정하지 않고 `zoom`을 쓴다(CLAUDE.md 8).
- **기준 화면은 휴대폰 폭 360~412px**이다. 새 칸은 360px에서 가로로 넘치지 않아야 한다.
- **새 디자인은 스위치 하나**(설정 → 앱 관리 "새 디자인")로 켜고 끈다. 예전 화면 코드는 사용자가 확정할 때까지 지우지 않고 `newLook ? 새 : 예전`으로 둔다.
- **달력 탭은 새 디자인에서 제외**다(사용자가 "원래 것이 좋다"고 되돌림). 다시 바꾸자고 하지 않는다.

## 1. 간격

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `gutter` | 16 | 화면 좌우 바깥 여백 |
| `box.pad` / `box.radius` / `box.gap` | 14 / 20 / 12 | 둥근 칸(`boxCard`): 안쪽 여백·모서리·칸 사이 |
| `titleGap` | 16 | **칸 제목 아래 여백.** 제목 바로 밑에 내용을 붙이지 않는다(2026-11-07 지적) |
| `headingGap` | 14 | 공통 `SectionHeading` 제목 아래 |
| `rowGap` | 10 | 목록 줄 사이 |
| `rowPadY` | 10 | 구분선 있는 줄의 위아래 안쪽 여백 |

- **접힌 칸**은 제목 아래 여백을 뺀다(`foldPad`).
- **제목 줄과 그 아래 한 줄짜리 조작부(‹ 날짜 › 등)** 사이에는 여백을 더 둔다. 접기 버튼과 조작 버튼이 맞닿으면 깨져 보인다(주간 일정, 2026-11-07).
- 칸 **안에 칸을 넣지 않는다.** 처음 안내·오늘 계획 같은 카드는 칸 위에 따로 둔다(CLAUDE.md 14.7).

## 2. 글씨

- **섹션 제목은 본문보다 작게 하지 않는다.** 17px 이상·굵게(`title`). 구분은 굵기·여백·아이콘으로 한다(2026-10-30).
- 보조 글씨는 **13px 이상**(`sub`). 새 디자인에서 11~12px는 쓰지 않는다. 흐린 버튼·작은 글씨는 또렷하게.
- 오늘 탭 할일 줄은 17px(`body`), 지금 할 일은 20px.
- 긴 제목은 **띄어쓰기 없이도** 화면을 넘지 않아야 한다: `wordBreak: 'keep-all'` + `overflowWrap: 'anywhere'`, 한 줄 목록은 말줄임. 그리드 안에서는 `minmax(0, 1fr)`(2026-11-07, 주간 일정이 가로로 넘친 원인).

## 3. 색

- **밝은 화면·어두운 화면 둘 다에서 확인한다.** 어두운 화면용 연한 색(`#C9D7FF`·`#c4b5fd`·`#b8c3ff`)을 밝은 화면 버튼에 쓰지 않는다.
- 강조색은 양쪽에서 보이는 `accent`(`#5B7CFA`)·`accent2`(`#8B5CF6`).
- 글자·배경은 `var(--dm-text)`·`var(--dm-sub)`·`var(--dm-muted)`·`var(--dm-card)` 등 테마 변수를 쓰고 색 값을 직접 쓰지 않는다.

## 4. 버튼·누르는 칸

- 전역 `button`에 좌우 padding 1.2em이 있다. **크기를 지정하면 `padding: 0`을 함께 쓴다.**
- 누르는 칸은 헤더 버튼 최소 32, 줄 안 주요 버튼(체크·아이콘) 40(`touch`). 칩·보조 버튼 높이 34(`chip`).
- **부가 버튼(순서 바꾸기 등)은 맨 아래가 아니라 제목 줄 오른쪽 빈자리에** 둔다(2026-11-07).
- 떠 있는 ＋ 버튼, 홈 화면 위젯은 만들지 않는다(CLAUDE.md 14.7·14.6).

## 5. 화면 구조

- **목록은 보기 전용, 편집은 상세 창**이다. 목록에서 바로 하는 것은 체크·언젠가·✕뿐(CLAUDE.md 14.1).
- **지우기·옮기기·완료 체크는 확인창 대신 5초 되돌리기**(`useUndo`). 서버에서 바로 지워져 못 되돌리는 것만 확인창.
- **순서 바꾸기는 "↕ 순서" 모드**(줄마다 ▲▼, 편집 중 체크·삭제 숨김). 끌어 옮기기·길게 누르기는 쓰지 않는다.
- **새 창·덮개·하위 화면에는 `useBackClose`**를 붙인다(CLAUDE.md 15).
- **시트·팝업은 `.dm-phone`에 포털**로 그린다(아래 메뉴에 가려지지 않게).
- 사진 첨부 input에 `capture`를 넣지 않는다(CLAUDE.md 7).
- 저장 실패 같은 문제는 **문제 있을 때만** 띠로 알린다("저장됨"을 매번 띄우지 않는다).

## 6. 새 칸·화면 체크리스트

만들거나 고친 뒤 **직접 화면으로** 확인한다(코드만 보고 끝내지 않는다).

1. **360px 폭**에서 가로로 넘치지 않는다. 긴 제목(띄어쓰기 없는 것)·습관·할일 여러 개를 넣어 본다.
2. **큰 글씨**(zoom 1.1)에서 제목과 버튼이 겹치지 않는다.
3. **밝은 화면·어두운 화면** 둘 다 글자가 보인다.
4. 제목 바로 밑에 내용이 붙어 있지 않다(`titleGap`).
5. 접은 상태·펼친 상태, 내용이 없을 때(빈 상태)를 본다.
6. 새 창이면 뒤로가기가 그 창부터 닫는다.
7. 새 디자인 스위치를 끈 예전 화면도 그대로 나온다.
8. 새 설정을 만들었으면 `utils/settingsSearch.js`에 한 줄, 기기별 값이면 `accountSwap`의 기기 설정 목록에 추가한다.
9. 테스트: `npm run test:smoke`에 새 화면 추가, 기록 이동 관련이면 `test:data`.

## 7. 탭별 새 디자인 적용 현황

오늘 ✅ · My ✅ · 설정 첫 화면 ✅ · 메모(쓰기 화면·목록·메모 관리자) ✅ · 소셜(커뮤니티·챌린지·자유게시판) ✅ · 달력 — 제외.
기준값(`UI`)으로의 숫자 이전은 오늘 탭부터 시작해 탭마다 차례로 한다. **기존 화면의 숫자를 한꺼번에 바꾸지 않는다.**
