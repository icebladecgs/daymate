## 사용자 요청 (2026-10-20)

- 유지: 하단 메뉴 모양과 6개 구성, 오늘 할 일이 한 화면에 쭉 나열되는 방식, 기존 기능·정보(임의 삭제 금지).
- 바꾸기: 글자가 빼곡하고 옛스럽고 촌스러운 인상 → 글씨 크게, 여백·우선순위 정돈, 색만이 아니라 배치·표현 변화, 할 일이 주인공, 진입·스크롤·체크 완료에 반응하는 움직임(단, 전체 목록을 빠르게 읽고 체크하는 편의는 유지).

## 진단 요약 (지금 화면)

할 일 제목이 14px로 화면에서 가장 작음 / 상자 안에 상자(첫 화면 테두리 상자 11개) / 입체 이모지가 하단 메뉴의 선 아이콘과 따로 놂 / 파랑을 10곳 넘게 사용 / 줄마다 체크·[언젠가]·✕ 버튼 벽 / 지금 할 일이 카드와 목록에 두 번 / 초 단위 시계가 "완료 2/6"을 가림 / 체크해도 반응 없음.

## 방향과 결론

- A 시간 흐름(시간 축), **B 또렷한 목록(추천)**, C 지금 한 장(카드 스택 — "한눈에 확인"과 충돌).
- 1차 B 시안은 첫 화면에 할 일이 3개만 보였다(머리글이 약 300px). 사용자에게 솔직히 알리고 **B 수정본**을 만듦:
  - 머리글: 날짜 13px + "4개 남았어요" 24px + 할 일 수만큼 칸 진행 막대. 요일 줄 얇게(숫자 16px). 어제 못 한 일은 노란 점 한 줄 띠.
  - 지금 할 일 = 목록 첫 줄(`NowTaskCard`를 목록에 합침): 연한 파랑 면, 20px, "지금 · 15:00–16:30 · 34분 남음", [완료][▶ 집중] 한 줄, 남은 시간은 칸 아래 가장자리 3px 선. [언젠가]·✕는 버튼 줄 오른쪽.
  - 나머지 줄: 한 줄 높이 50px — "19:30 엄마한테 전화하기 🤝"(시간 15px은 있을 때만, 제목 17px·500, 능력치 이모지 13px). 체크는 26px 동그라미(누르는 영역 44px). [언젠가]·✕는 테두리 없는 회색 아이콘.
  - 목록 끝 "+ 할 일 추가" 줄, 그 아래 "완료 n" 묶음(완료 줄 44px).
  - 아래 보조 섹션: 챙길 사람 → 습관(3칸 고리 타일) → 언젠가(3개+더 보기) → 주간 일정(접힌 한 줄) → 일기. 섹션 제목은 13px 회색 이름표 + 선 아이콘.
  - 측정: 예시 6개 기준 어제 못 한 일 띠가 없으면 6개 모두, 있으면 5개와 반 줄이 첫 화면에 보임(지금 앱과 같은 수).
- 색: 파랑은 지금 할 일·선택한 날·주요 버튼만, 초록은 완료만, 노랑은 어제 못 한 일만. 유리·블러·그림자·배경 번짐 없앰.
- 움직임: 진입 시 줄이 차례로 14px 떠오름(45ms 간격, 8줄까지) / 스크롤하면 위에 "오늘 2/6 + 막대" 작은 띠 / 체크 시 동그라미 튐+취소선 그어짐+진동 / **마지막 체크 0.7초 뒤** 완료 묶음으로 미끄러짐(FLIP 420ms) / 체크 풀면 원래 자리로 / 움직임 줄이기 설정 존중.
- 참고 앱: Things 3, 미리 알림, Todoist, Microsoft To Do, Structured, 구글 캘린더, Tiimo, TickTick.

## 사용자에게 아직 확인받지 않은 것 (구현 전에 정할 것)

1. 목록 줄의 [언젠가]·✕ — CLAUDE.md 14.1 유지, 모양만 회색 아이콘으로 (추천)
2. 끝난 할 일을 아래 "완료" 묶음으로 모으기 — 순서가 바뀜. 써 보고 별로면 끌 수 있게 (추천)
3. 섹션 이모지만 선 아이콘으로, 능력치 이모지는 작게 유지 (수정본에 반영)
4. 머리글 시계 초 단위 → 분 단위
5. 적용 범위 — 공통 스타일(`styles.js`)은 다른 탭도 바뀌므로 오늘 탭 전용으로 먼저

사용자는 수정본을 휴대폰으로 보고 고칠 점을 알려주기로 함. 그다음 위 5개를 정하고 오늘 탭부터 구현.

## 구현할 때 주의

- 바뀌는 곳: `src/screens/Today.jsx`, `src/components/NowTaskCard.jsx`(목록 첫 줄로), `src/components/WeekStrip.jsx`, 새 할 일 줄 컴포넌트, 애니메이션 CSS(`index.css`). 데이터·Firestore·규칙·서비스워커는 건드리지 않는다.
- **큰글씨 `zoom`(`.dm-phone`에 1.1)과 FLIP:** `getBoundingClientRect`는 확대된 값을, `transform: translate`는 확대 전 단위를 쓰므로 이동 거리를 확대 배율로 나눠야 한다. 시안에서도 같은 문제로 `transform: scale`로 우회했다. 실제 기기(구형 안드로이드 포함)에서 끊김 확인.
- 전역 `button` padding(CLAUDE.md 15장) 때문에 버튼 크기가 커지는 문제 — 시안에서도 같은 종류의 실수가 있었다.
- 애니메이션 라이브러리 없이 CSS + 작은 FLIP 함수로(번들 크기 유지).
- 검증: 기본 점검·기록 보존 점검 + 휴대폰 폭·큰글씨에서 할 일 0·6·20개, 시간 있는 날/없는 날, 다크·라이트 캡처.
