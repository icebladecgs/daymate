# Decisions

## Versioning
- 앱 버전은 수동 문자열 대신 자동 생성 방식을 유지한다.
- 이유: Vercel/로컬 빌드 사이 불일치와 `v0` 회귀를 막기 위함.

## Telegram Host
- 기본 텔레그램 호스트는 Mac이다.
- 이유: 항상 켜두는 운영 머신을 하나로 정리해야 polling 충돌을 피할 수 있다.

## Home Ordering
- 습관 순서 변경은 드래그 방식으로 유지한다.
- 습관 드래그는 오버레이보다 원본 행 이동 방식을 우선한다.
- 이유: 모바일 터치에서 손가락 위치와 시각적 위치가 더 잘 맞는다.

## Update UX
- 설치형 앱에서는 업데이트 준비 상태를 앱 안 배너로 명시한다.
- 이유: 서비스워커 교체가 사용자가 보기엔 불투명하기 때문.

## Per-Entity Firestore Documents for Growing Data (2026-09-21)
- 사람/기록처럼 계속 늘어나는 데이터는 `users/{uid}/data/settings` 같은 단일 설정 문서에 필드로 얹지 않고, `days`와 동일하게 `users/{uid}/contacts/{contactId}`처럼 엔티티별 개별 문서로 저장한다.
- 이유: `settings` 문서는 로그인마다 통째로 1번 읽고 `merge:true`로 통째로 쓰는 구조라, 배열 필드는 append가 아니라 항상 전체 교체다. 계속 쌓이는 데이터를 여기 넣으면 로그인마다 읽는 문서가 커지고, Firestore 1MiB 문서 한도 위험도 생긴다. 앞으로도 "기록이 쌓이는" 성격의 새 기능은 이 패턴(엔티티별 개별 문서)을 기본으로 따를 것.

## Lunar Calendar Conversion (2026-09-21)
- 음력 생일 변환에는 `korean-lunar-calendar`(npm, KASI 변환표 기반, 1000~2050년 지원, 의존성 0개) 라이브러리를 쓴다.
- 이유: 자체 구현은 윤달 처리가 까다롭고 검증이 어려움. 다만 이 앱은 생일을 "연도 없이 월/일만" 저장하므로 그 월/일이 실제로 윤달이었는지는 알 수 없다 — 변환 시 평달로 가정한다(폼에 안내 문구 있음). 정확한 변환이 필요한 다른 기능(기타 기념일 등)은 현재 양력만 지원.

## Cron Frequency (2026-07-17)
- `push-morning`(잠금화면 아침 알림) cron은 사용자별 알람 시간에 맞춘 폴링(하루 6회) 대신 하루 1회 07:00 KST 고정으로 유지한다.
- 이유: Vercel Hobby 플랜은 cron 하루 1회 초과 시 배포 자체를 거부한다. 이 제한을 넘겼던 커밋(v422) 때문에 3주간 배포가 막혀 있었다([[known-issues]] Deploy Pipeline Silent Failure). 유연한 시간을 되살리려면 Vercel Pro 업그레이드가 선행돼야 하며, 이는 비용이 드는 결정이라 사용자 승인 없이 진행하지 않는다.
